# 同步冲突设计

状态：**阶段 4 候选方案，尚未实现或通过三端收敛验收**。当前数据库没有服务器 revision / operationID 表；现有客户端仍按原 updatedAt 协议运行。本文不是已经修复 C02/C03/C05/C17 的声明。先执行下述共享模型测试、隔离副本迁移测试，再实现兼容扩展。

## 1. 目标与不可破坏的边界

- 修改/删除都需要目标版本；冲突保留双方内容并明确报告，不默默取某个设备的时间作为事实。
- 保留原集合、ID、updatedAt、deletedAt、字段和旧同步入口；新客户端采用可选协议版本。没有协商成功就不能发 revision 写请求。
- 不批改历史 ID/时钟、不清空或按年龄淘汰 tombstone、不永久删除优先、不自动恢复被删除记录。
- 不在生产执行迁移、压力测试、密钥轮换或部署。照片只读引用扫描另见阶段 6。

## 2. 建议的扩展信封

现有快照字段继续原样返回，新增可选字段：

```json
{
  "protocolVersion": 2,
  "revisions": {"meal:记录ID": 42},
  "acknowledgedOperationID": "设备生成的稳定操作ID",
  "conflicts": []
}
```

写请求带 `operationID`、逐目标 `baseRevision` 和变更列表。operationID 在发请求前写本机持久 outbox，超时/重启重试沿用同一个值；不能每次网络重试生成 UUID。旧端继续发送完整快照。

服务器为同账号分配单调 revision，每项成功变更/删除持有 revision；客户端时间只保留为业务时间/兼容显示，不作为新协议冲突裁决依据。新记录 baseRevision=0；已有 ID 不得被当成另一条 add。settings 的键固定为 profile。

服务端需要最小新增元数据表（版本/操作摘要与回执），不重写 record_fields 中的历史 payload。上线前必须在隔离副本检查旧 schema、事务中断、未来 schema、版本冲突、foreign_key_check 和内容摘要；尚未进行此迁移。

## 3. 变更的原子规则

1. 锁定账号版本，在同一 SQLite 写事务中检查 operationID。相同 ID/相同请求摘要重试返回已提交回执；相同 ID/不同摘要返回明确冲突，不能再次执行。
2. 先检查所有目标的 baseRevision。任一不匹配则整批 409，零写入，返回当前 revision、当前快照及冲突目标；不在失败响应中隐含执行其余动作。
3. 全部匹配后验证输入、保留未编辑字段，写记录/删除标记/回执并分配 revision。记录事务与回执事务必须一致，不能先标记操作成功再写数据。
4. 响应丢失时，重试不重复新增、删除或上传绑定。回执返回当前可读取版本，不能把过期缓存快照重新覆盖最新状态。
5. 以服务端版本为准的当前客户端要区分“已确认服务器版本”和“本地待提交草稿”。409 不得把待提交内容覆盖成服务器内容；先保存冲突副本和原稿，供用户核对/导出。

删除不是永久胜者：并发删除/编辑先提交的一方成功，另一方遇版本冲突；用户明确恢复时需基于当前 tombstone revision 提交恢复操作。不能自动将晚到的离线修改解释为恢复意图。相同内容重复发送幂等；同时间不同内容不能交替覆盖。

## 4. 旧客户端兼容

- 保留旧 POST /sync 和 GET /snapshot、原 timestamp 字段；忽略新响应字段的旧端仍能读取。
- 同内容同时间无写入；过期快照不得覆盖新数据。相等时间不同内容应返回可理解的冲突，保留服务器当前版本和入站冲突证据，不无限覆盖。
- 旧协议没有 baseRevision，不能可靠区分“离线旧修改”与“时钟慢的新修改”。不能宣称仅加服务器时间就解决该歧义。遇到可能覆盖较新版本的请求，应显式提示使用新端核对，不能静默接受或批改所有历史时间。
- 更新后的当前客户端采用 revision 后，不再让未来客户端时钟长期压制正常操作。为旧端可见性维护兼容更新时间的具体算法需先测上界/未来 30 天/回拨，不能未经验证把全库时间统一改成 now。
- 不自动废止旧客户端或修改同步密钥；兼容冲突提示、恢复流程和旧端可读性必须纳入发布阻断清单。

## 5. iOS/Android/Web 与 AI

- 三端持久保存每目标已确认 revision、本地操作 ID、baseRevision 和待提交变更。只有收到对应回执才确认 outbox；全量响应不删除尚未确认的本地草稿。
- iOS 删除键必须逐版本比较；保留 tombstone。不能继续“存在删除键即永远跳过”，也不能通过清空所有删除键使数据复活。
- 训练编辑保存时重新找目标，核对打开时版本/是否被删除，保留旧草稿并提示重核。
- AI 请求固定生成时目标版本；返回后逐目标核对。无关记录变化不应废掉整个回答；目标已变则该批次明确冲突。AI 权限和删除确认还需单独验证 R01。
- Web 新建表单在打开草稿时生成 ID 和 operationID；超时重试复用。移动端 AI 新建操作绑定用户消息与执行计划，不因相同请求重试创建新记录。
- 网络压缩、多图上传、模型等待及重试都需要固定账号代次；账号切换使旧任务失效，不能把旧 outbox 搬到新账号。

## 7. 回滚与上线边界

保留旧读取路径；新增表/字段保持兼容，不以回滚为由删除服务器版本、幂等回执、冲突副本或 tombstone。关闭新写路径后旧端仍可能受到旧时间规则限制，不能声称直接回滚服务器即可无损恢复所有并发操作。迁移、回滚副本演练及发布验证均未完成，生产不具备部署授权。
