# Android 一致性优化实施记录

2026-10-21。本机源码按[检查报告](android-ios-audit-2026-10-21.md)实施全部七组优化，沿用 Kotlin / Compose 原生工程与现有数据协议。iOS 作为页面结构和行为参照，本轮没有修改 iOS、Web 或服务端。按用户后续授权将改动发布为 [Android 1.4.0-beta.7](android-release-1.4-beta7.md)。

## 已实施

| 范围 | 最终行为 |
| --- | --- |
| 编辑草稿 | 餐食、身体测量、训练及动作逐组数据、常用餐食、动作库的编辑入口和字段支持系统状态恢复；个人目标草稿也保留。放弃改动前可继续编辑或确认放弃，读取照片和 AI 处理时阻止误关闭/保存。 |
| 草稿照片 | SavedState 只存私有照片文件的引用。拍照 URI、待处理相册 URI 和读取队列可恢复，读取完成后释放相册授权；保存或明确放弃后清理本次草稿照片。历史非 UUID 记录 ID 使用哈希目录，不改变记录本身的 ID。 |
| 识别模式 | 增加“餐盘识别 / 营养成分表 / 配料表”，分别处理同餐多角度去重、每份/每 100g 与实际摄入量换算、配料和不确定性。结果继续复核后手动保存。 |
| 多图浏览 | 餐食和聊天均进入同组图片查看器：左右翻页、序号、前后按钮、保存当前图片、双击与双指缩放、还原比例后下滑关闭；放大时优先平移，不切换页面。 |
| 周历与同步 | 首页用每日蛋白质、碳水与餐次数生成三色小圆环；大字体下日期独立显示。补齐餐次图例、下拉同步及就近结果提示，保留原有自动同步。 |
| 餐食快捷操作 | 长按餐食可编辑或删除，删除沿用确认提示。恢复的旧编辑草稿无法重新保存已删除记录，保留更新版本冲突检查。 |
| 身体总览 | 同图展示中位数灰色虚线与趋势实线，坐标域覆盖两者并提供图例；优先展示今日测量，历史按需展开。 |
| 长列表 | 餐食历史、照片列表、测量详情、全部记录、常用餐食/动作库改为稳定 ID 的 LazyColumn。小缩略图按尺寸解码，大图仅加载当前页及相邻页。 |
| 统一材质与控件 | 卡片启用实际 tint 材质、统一 26dp 圆角；单选控件统一样式并在大字体/窄屏下纵向排列；修正外观调色盘图标。聊天气泡使用当前强调色与语义文字色。 |
| 反馈与无障碍 | 保存成功/错误、重要确认及教练完成/失败使用系统触觉反馈，尊重系统设置。周历播报记录与营养状态，趋势/柱状图提供当前读数和前后日期操作，照片提供放大/还原操作。大字体图表为坐标标签预留实际宽度。 |
| 动态与模糊性能 | 系统关闭动画时省略按钮/标签按压缩放；主题内统一观察系统设置。渐进模糊支持省电模式回退；根据滚动采样，将嵌套 AGSL 采样改为三档系统高斯平滑融合，背景以四分之一宽高渲染并限制扩展采样区，文字和图标维持完整分辨率。 |

聊天的强调色跟随为本轮安卓改进；iOS 当前气泡仍使用固定 AppTheme.accent，不宣称该项两端已经完全一致。

## 验证范围

- Debug / Sandbox 构建成功；两种构建各 69 项 JVM 测试全部通过，无失败、错误或跳过。Lint 均为 0 错误，Debug 16 项、Sandbox 15 项既有兼容/代码建议警告。
- API 35 独立模拟器完整 54 项设备测试全部通过：5 项账号流程、13 项本轮一致性检查、23 项操作流程、3 项材质像素检查、3 项隔离检查、7 项存储检查。
- Kotlin 实际生成的 JSON 与后端字段往返检查、同步编辑/删除兼容检查通过（`Tests/android-sync.py`、`Tests/sync-edit.py`）。
- 所有设备测试仅针对独立 `.instrumented` 包；安装前检查无 INTERNET 权限、独立应用与数据库、fake 网络。
- 草稿重建检查覆盖五类记录和嵌套逐组编辑，成功保存后的记录身份与营养值不变；检查确认放弃、已删除记录拒绝重新保存、历史 ID 的照片暂存兼容。
- 识别模式使用模拟上游，核对实际请求提示词与不自动写入记录；不消耗计费 AI。
- 图片检查包含连续翻页、边界按钮、缩放状态和翻页互斥；千条餐食历史可按需滚动至最后一条。
- 2 倍字体下检查识别类型可见与布局；图表语义操作直接执行前后日期切换。
- 全流程包含账号注册/登录/隔离、手动餐食与训练、跨标签搜索/草稿、质量确认、周报、照片留存/保存，以及深浅色和键盘流程。

系统状态恢复覆盖活动重建与 SavedState 恢复路径；没有把强行清除应用数据或主动移除任务后的草稿当作永久草稿库。完整 TalkBack 语音阅读顺序、API 26–32 系统镜像、真实低端手机帧率及长时间温升仍需对应设备验收。模拟器采样用于发现明显回归，不能替代真机性能结论。

滚动采样使用同一 API 35 / 1080×2400 模拟器，首页示例数据上下各滑动三次，记录 `FrameMetrics.TOTAL_DURATION`：SwiftShader 的 32 帧 p50 / p95 为 144.84 / 176.13ms；宿主 Apple M5 / Metal 的 55 帧为 33.82 / 44.34ms。宿主 GPU 追加检查与省电切换均通过。这些为 Debug、自动化、模拟器环境下的小样本，包含调度开销，未达到可据此承诺 60fps 的证据；仅用于确认软件渲染瓶颈和记录后续真机检查的起点。原始数据：[SwiftShader](../Android/screenshots/parity-completed-2026-10-21/frame-profile-swiftshader.json)、[宿主 GPU](../Android/screenshots/parity-completed-2026-10-21/frame-profile-host.json)。
