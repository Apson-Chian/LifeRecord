# Android 1.4.0-beta.2

2026-10-15。以当前 `iOS/`（对齐基线 `70cbf31`）为参照，保留独立 Android 工程。本轮不修改 iOS、Web、后端和用户数据。

## 下载和覆盖安装

[GitHub Release](https://github.com/Apson-Chian/LifeRecord/releases/tag/android-v1.4.0-beta.2) 的 Assets 提供 `LifeRecord-Android-1.4.0-beta.2.apk` 和 `SHA256SUMS.txt`。使用安卓手机下载 APK，在文件管理器中打开，并按系统提示允许该来源安装应用。旧测试版直接覆盖安装，不需要卸载；卸载会删除未同步的本机数据。最低 Android 8.0 / API 26，目标 API 35。

版本号 `1.4.0-beta.2`，versionCode `6`。APK 来自 Release 变体，未启用应用调试；为了兼容已有测试版，沿用同一个测试证书。证书 SHA-256：`217a683e9e34047e07205651ae92575f206db141f42fb1c1b48523a3e32103e5`。签名私钥、APK 和本机数据不进入源码仓库。

## 页面与交互对齐

| Before | After | Why |
| --- | --- | --- |
| 训练仅概览与列表 | 周一开始的月历、上/下月、回到本月、日训练量、训练内容、当天明细及直接编辑原记录 | 对齐 iOS 新增月历路径 |
| 固定 AI 标题和头像 | 顶部头像/名称/对话标题，点击打开资料；设置中也可更换名称、相册头像或恢复默认 | 保持当前 iOS 的教练身份和入口 |
| 写入开关藏在设置，旧的草稿确认流程 | 输入栏常驻“允许 AI 修改记录”；开启后按请求验证操作，数据库提交成功才展示应用回执 | 对齐当前 iOS 交互，避免只在聊天中声称保存 |
| 生成时只能等待，单一忙碌状态 | 生成卡与发送位均可停止，取消对应 OkHttp 请求；每个对话独立生成状态 | 离开/切换页面继续生成，也能由用户停止 |
| 应用外观切换后系统栏仍跟随系统 | 状态栏图标和导航栏图标跟随应用当前深浅色 | 避免浅色页面白字或深色页面黑字 |
| 只有相册选择 | 教练与餐食识别提供系统拍照/相册选择菜单 | 对齐图片输入方式，保留原图压缩与私有保存 |

沿用并验证最近的六入口设置、合并个人与营养目标表单、按历史时段回顾的目标反馈、默认折叠的详细解读、最新消息定位、未发送草稿保留以及玻璃导航。

月历的负重 × 次数仅统计实际填写的正数；无有效组数据时显示“已训练”，不推测负重。跨午夜归入开始日，进行中、结束在未来或起止时间不合法的训练不计入完成次数与分钟。日明细保留部位、备注、全部动作和逐组数值。

名称和头像仅保存在这台设备，所有对话共用，不进入同步、导出或 AI 图片请求。头像居中裁切并压缩为 512 × 512 JPEG，限制 512 KB。相机通过不可导出的 FileProvider 共享本次 `cache/camera/` 临时文件，未开放数据库或其他私有目录；拍照完成或取消时清理临时文件。

AI 写入默认关闭。模型返回操作但未授权时显示“未保存”；没有有效操作时不会仅凭模型文字声称已执行；未知记录 ID、参数无效或响应期间数据已变化会阻止整批写入。记录的用户原始描述、AI 估算来源、对话编号和当前请求的餐食照片一并保存。停止请求保留已发送的问题与聊天附件，不执行该次操作。

## 已知平台差异

Android 使用 RenderEffect/AGSL 近似 Liquid Glass，系统字体、选择器、返回和键盘遵循安卓平台。训练详情内的专用 AI 部位分类/部位管理页面仍未移植；教练可按明确要求修改部位，手动部位与动作编辑保留。聊天、头像、常用餐食照片、质量确认与周报仍为本机保存。未使用用户密钥调用真实计费 AI；未在 API 26–32 的旧设备上运行本轮新增流程。
