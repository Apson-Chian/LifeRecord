# Android 12 兼容、示例与材质修正

2026-10-21–22，Android 1.4.0-beta.8 / versionCode 12。对应用户报告的真我 Android 12 残影、点空白不收键盘、示例单调、AI 数据范围不清，以及圆环和卡片层次问题。

## Android 12 残影

beta.7 只在 API 35 上运行设备回归，没有覆盖 Android 12，这是此前的验证缺口。API 31 的背景 RenderNode 被更新时，引用它的滤镜节点不一定随之刷新，可能继续显示旧的采样块。Haze 的[平台说明](https://chrisbanes.github.io/haze/dev/blur/platforms/)也明确记录了 Android 12 的额外重绘和 API 31 滤镜重建需求；这与用户报告的残留小块相符，但没有直接调试用户真机来断言唯一原因。

本次在 API 31–32 对采样和滤镜的绘制节点监听 Snapshot 更新，主动使绘制缓存失效；API 31 同时重建滤镜，避免复用旧输入。监听不写入 Compose 状态，不创建永久空闲动画，并在节点分离时注销。API 33 以上保留原生刷新路径。低内存、省电及旧系统回退继续生效。

新增像素回归直接检查模糊区的红/蓝内容更新、子图层变换和反复退出/进入。它检查的是滤镜输出，补足先前只检查清晰上缘更新的不足。使用官方 AOSP Android 12 / API 31 ARM64 镜像和 Android 15 / API 35 镜像；无法替代真我及 vivo 的对应固件、驱动与长时间真机验收。

## AI 实际可以看到什么

此前安卓和 iOS 都传入本机全部真实餐食、测量和训练，未按当前图表时间范围截断；但示例被排除。安卓复用同步快照构造模型上下文，导致示例界面有数据而 AI 没有数据。iOS 的近期摘要之外也有全量真实记录清单，iOS 的首页新增与字体比例跟进见下文。

安卓现使用独立 `CoachContext`：

- 普通对话读取全部本机真实记录、营养与原始输入、身体测量、训练动作/逐组数据、常用餐食、动作库、个人目标，并提供数量和本地时间。
- 明确选中的示例对话使用合成示例和示例目标；该范围只读，模型返回动作也不会执行。新建普通对话使用真实数据，不混合样本；即使尚无真实记录，也可在新对话中录入第一餐。数据范围弹层可直接切换到示例或新建真实记录对话。
- 教练页新增“数据范围”，可查看范围、各类记录数量和不可见内容；“允许修改”在示例范围禁用，不改变用户对真实数据的写入偏好。
- 当前对话只携带最近 14 条消息，以及本次附图；不自动读取其他对话、历史照片字节、密钥或尚未同步到本机的数据。文件路径不进入模型上下文。
- 没有悄悄截断旧记录；默认服务仍有单次 18 万字符及模型上下文上限，超出时会拒绝请求，不能据此声称无限数据都能在一次请求中处理。本轮没有修改或部署后端。

## 示例与视觉

30 天内的示例增加 18 种餐食、份量原始输入、不同日摄入、五类训练轮换、休息日、力量/计时组、同日两次测量、常用餐食和动作库。未发生的今日餐次和训练不提前补齐，也不再全部压到当前时间；凌晨无今日事件时，首次预览跳到最近有数据的日期。

示例目标独立用于首页和趋势预览，个人设置不被覆盖。更新和清除示例保留真实数据；所有示例类型均排除在同步和导出之外。原有示例不会静默替换，升级后到“设置 → 隐私、数据与帮助 → 载入完整示例”更新。

圆环按当前 iOS 源码使用 116dp 主圆环 / 14dp 线宽、42dp 周历 / 5dp 线宽，补齐角向渐变、软阴影、光晕和数字/餐次两层文本，尊重关闭动画的设置。卡片统一分组底色、0.055/0.13 的深浅色主题渐变、1dp 边框和浅色双层轻阴影，覆盖首页、快捷卡片与设置分组；页面背景增加轻微主题色过渡。安卓字体和阴影栅格化仍有平台差异。

## 键盘

页面与表单监听未被控件处理的轻触，点空白后清除焦点并收起键盘；输入框、按钮、文字选择和滚动优先处理，不吞掉原操作。显式“收起键盘”也清除表单焦点。回归检查草稿保留、导航恢复及再次点击其他输入框能唤起键盘。

## 2026-10-22：字体、比例与 iOS 首页

Android 明确设置全部文字角色与行高，去除多余字体留白，保留系统字体缩放。按 iOS 层级重排首页：目标标题、圆环与蛋白质/碳水/体重图例、底部 34sp 热量数字；快捷入口改为上方图标、下方标题与说明。页面标题、卡片标题、正文与小字分层，主字体继续使用安卓系统 Sans，未打包苹果专有字体。

教练消息采用 15sp / 22sp 行高；输入文字 15sp / 21sp 行高，Markdown 标题分级，图片为 84dp 双列缩略图。把数据范围合并到写入权限区域，减少一行顶部占用；保留 44dp 输入操作按钮。短对话按 iOS 底部对齐，键盘聚焦或字体变化时保持最新回复可见。大字体下加高标题栏，并保留可滚动消息视口和可达输入框。标准字体和 1.8 倍字体实际截图验收，不把禁用用户字体缩放当作两端一致。

趋势搜索和筛选提升至页面级 SavedState，避免条件子页被重新组合时丢失跨标签查询。

iOS 首页在餐食记录后新增所选日期的身体测量，显示时间、体重、体脂、腰围与备注，可进入测量详情、编辑和全部历史；无记录时可从该日期直接添加。沿用真实/示例数据筛选和现有冲突校验。复用原质量检查的身体详情，未新增第二套保存路径。体脂编辑框去除浮点长尾，仅调整日期、体重或备注时仍保留原始体脂精度。

## 2026-10-22：跟手弹簧

使用 Compose 原生 `Animatable` 与拖动 API，参考 Android 官方[手势动画示例](https://developer.android.com/develop/ui/compose/animation/advanced)及其链接的 GitHub 示例。扩展现有弹簧参数，未增加动画依赖；统一 `SpringMotion`，按钮/快捷卡片、教练操作按钮及分段选项沿用阻尼 1 / 刚度 850 的轻微按压，导航点选阻尼 1 / 刚度 700，只有带动量的手势松手使用阻尼 0.8 / 刚度 380。

导航拖动直接写入屏幕位置，超过两端时采用逐渐增强的阻力；松手用速度投影选择落点，位置与速度连续接入弹簧。点击其他标签会从当前呈现值重新定位，回弹过程中按下即暂停并可反向拖动，不等待旧动画结束。位置用图层平移，按压用图层缩放，不逐帧修改布局尺寸，不锁定输入。

照片下滑同样实时跟手；未达到关闭条件时弹回，达到条件时继续向下离开。手指按下会暂停正在进行的回弹或关闭；缩放、横向翻页及双击还原保留原交互优先级。系统动画关闭时移除按压缩放、吸附和弹回位移过程，保留原生按压明暗与选中反馈，保持可操作。

四项设备回归使用受控 Compose 帧时钟，检查拖动位移增量、松手不跳变、途中重新抓取和反向、按压取消不执行保存、短照片拖动回弹，以及关闭动画后选中位置直接到达。它们验证状态和帧间连续性，不代替真机上的手感、刷新率和温升验收。
