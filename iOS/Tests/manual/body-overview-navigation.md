# 身体总览导航回归

## 问题与修复

在 iOS 26.5、iPhone 17 Pro 隔离模拟器上，载入完整示例（28 条测量），进入「趋势 → 右上角数据详情 → 身体总览」会停在数据详情，无法完成导航。

主线程采样显示 SwiftUI/AttributeGraph 持续重建 `BodyDashboardView`，CPU 约 99%。临时 `_printChanges()` 记录连续数千次 `@self changed`；移除图表后仍然卡住，因此不是图表绘制或记录数量导致。诊断代码均已移除。

`BodyDashboardView` 原先在嵌套导航目标中重新建立身体、真实餐食、真实训练三组 `@Query`。改为接收趋势页已经查询、排序并完成示例/真实隔离的身体记录后，同一导航正常完成；主线程采样恢复为 run loop 等待，CPU 空闲时为 0%。父页面继续持有实时查询，新增和清空记录仍会更新已打开的总览。

## 手动验证步骤

使用独立模拟器及合成记录，不连接真实账号。

1. 全新安装，首次导览选择「先体验完整示例」。
2. 进入「趋势 → 数据详情 → 身体总览」。确认趋势体重、双曲线、身体组成和今日测量正常加载。
3. 返回数据详情，再次进入身体总览。确认导航正常响应。
4. 切换「今日」，清除测试示例，再切回仍处于身体总览的「趋势」。确认显示「暂无体重记录」「暂无体脂数据」，不残留示例数值。
5. 切换「今日」，保存一条 70.0 kg 的合成测量（不填写体脂），再切回身体总览。确认趋势体重和今日中位数均为 70.0、今日测量为 1 次、体脂保持缺失状态。
6. 停留页面后采样主线程，确认没有持续的页面重建和 CPU 满载。
